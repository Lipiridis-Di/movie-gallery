Это документ, где мы до написания кода продумываем "скелет" проекта: какие будут файлы и папки, какие данные мы храним и в каком виде, как страницы общаются друг с другом. Если это сделать заранее, на этапе генерации кода не придётся на полпути всё переделывать. Ниже — каждый раздел с объяснением, зачем он вообще нужен, не только "что делать".

## 1. Структура папок проекта

Идея разделения на папки простая: код, который делает разные вещи, лежит в разных местах, чтобы через месяц было понятно, где что искать.

```
src/
  api/          — весь код, который "ходит" в TMDB (интернет-запросы)
  types/        — описания форм данных (TypeScript-типы): что такое "фильм", "актёр" и т.д.
  components/   — переиспользуемые кусочки интерфейса (карточка фильма, кнопка, лоадер)
  pages/        — целые страницы сайта (Главная, Страница фильма, Избранное)
  router/       — таблица маршрутов ("какой адрес — какая страница")
  store/        — глобальное хранилище состояния (Zustand), сейчас — только избранное
  App.tsx       — корневой компонент, собирает роутинг и общий layout
  main.tsx      — точка входа, здесь React "монтируется" в HTML-страницу
```

## 2. Типы данных (TypeScript)

Тип в TypeScript — это описание "формы" объекта: какие у него поля и какого они типа. Это не меняет то, как работает JavaScript, но позволяет редактору подсказывать вам ошибки ещё до запуска кода (например, если вы опечатались в названии поля).

Данные о фильмах мы получаем от TMDB API, поэтому типы описываем по документации TMDB:

```typescript
// types/movie.ts

// Один фильм в списке (каталог, поиск, избранное)
export interface Movie {
  id: number;
  title: string;
  poster_path: string | null; // может не быть постера
  release_date: string; // "2024-03-15"
  vote_average: number; // рейтинг, например 7.8
  genre_ids: number[]; // список ID жанров
}

// Подробная информация о фильме (страница фильма)
export interface MovieDetails extends Movie {
  overview: string; // описание
  runtime: number; // длительность в минутах
  genres: Genre[]; // здесь уже не ID, а полные объекты жанров
}

export interface Genre {
  id: number;
  name: string;
}

export interface CastMember {
  id: number;
  name: string;
  character: string; // какую роль играет
  profile_path: string | null;
}

// TMDB почти всегда возвращает списки в таком "конверте" с пагинацией
export interface PaginatedResponse<T> {
  page: number;
  results: T[];
  total_pages: number;
  total_results: number;
}
```

`PaginatedResponse<T>` — это "дженерик" (обобщённый тип): один и тот же конверт с пагинацией подходит и для списка фильмов, и для списка чего угодно ещё, поэтому мы не пишем его заново для каждого случая.

## 3. Слой работы с API

Здесь — весь код, который обращается к TMDB через интернет. Идея: остальной код (компоненты) не должен знать, как именно устроен запрос — он просто вызывает функцию вроде `getPopularMovies()` и получает готовый результат.

Что нужно для начала:

- Зарегистрироваться на TMDB и получить бесплатный API-ключ.
- Положить ключ в файл `.env` (переменные окружения) — это файл, который **не** попадает в git/GitHub, чтобы ключ не утёк наружу. В Vite такие переменные должны начинаться с `VITE_`, например `VITE_TMDB_API_KEY`.

Базовая функция-обёртка, через которую идут все запросы:

```typescript
// api/client.ts
const BASE_URL = "https://api.themoviedb.org/3";
const API_KEY = import.meta.env.VITE_TMDB_API_KEY;

async function tmdbFetch<T>(
  endpoint: string,
  params: Record<string, string> = {},
): Promise<T> {
  const url = new URL(BASE_URL + endpoint);
  url.searchParams.set("api_key", API_KEY);
  Object.entries(params).forEach(([key, value]) =>
    url.searchParams.set(key, value),
  );

  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`TMDB request failed: ${response.status}`);
  }
  return response.json();
}
```

А дальше — конкретные функции, которые дергают этот общий механизм с нужным адресом (endpoint):

- `getPopularMovies(page)` → `/movie/popular`
- `searchMovies(query, page)` → `/search/movie`
- `getMovieDetails(id)` → `/movie/{id}`
- `getMovieCredits(id)` → `/movie/{id}/credits` (актёры)
- `getMovieVideos(id)` → `/movie/{id}/videos` (трейлеры)
- `getGenres()` → `/genre/movie/list`

## 4. Роутинг (React Router)

Роутинг — это то, что превращает адрес в браузере (`/movie/42`) в конкретную страницу, которую видит пользователь, без перезагрузки всей страницы браузером (в этом разница с обычным сайтом на отдельных HTML-файлах).

Таблица маршрутов для нашего проекта:

| Адрес        | Страница         | Что показывает                    |
| ------------ | ---------------- | --------------------------------- |
| `/`          | HomePage         | популярные фильмы, поиск, фильтры |
| `/movie/:id` | MovieDetailsPage | подробности одного фильма         |
| `/favorites` | FavoritesPage    | избранные фильмы пользователя     |

`:id` в адресе — это "динамический параметр": подставляется настоящий ID фильма (`/movie/42`), и компонент страницы читает его через хук `useParams()`, чтобы понять, какой именно фильм грузить.

Поиск и фильтры (жанр, год) мы делаем не отдельной страницей, а через **query-параметры** прямо в адресе главной страницы: `/?q=matrix&genre=28`. Это удобно тем, что такой адрес можно скопировать и отправить другу — он откроется с теми же фильтрами. Читаются такие параметры хуком `useSearchParams()`.

## 5. Глобальное состояние (Zustand)

Сначала — зачем это вообще нужно. У React есть свой способ хранить данные внутри одного компонента — `useState`. Но если хочешь добавить фильм в избранное на странице `/movie/42`, а потом увидеть его в списке на странице `/favorites` — это уже два разных компонента, и `useState` между ними данными не поделится. Вот для этого и нужно "глобальное" хранилище — данные, доступные из любого места приложения.

Zustand — это библиотека для такого хранилища, с более простым API, чем у Redux. Нам оно нужно только для избранного:

```typescript
// store/favoritesStore.ts
interface FavoritesState {
  favoriteIds: number[];
  addFavorite: (id: number) => void;
  removeFavorite: (id: number) => void;
  isFavorite: (id: number) => boolean;
}
```

Плюс — middleware `persist`, который сам сохраняет это хранилище в `localStorage` браузера, чтобы избранное не пропадало при перезагрузке страницы.

Фильтры и поиск, как договорились в разделе про роутинг, в Zustand **не** кладём — они живут в адресной строке. Это специально показать разницу: не всё состояние должно быть "глобальным", иногда состояние — это просто часть URL.

## 6. Компоненты

**Layout:**

- `Header` — логотип, поле поиска, ссылка на избранное.
- `Layout` — общая обёртка страницы (Header + место для содержимого страницы).

**Переиспользуемые (общие):**

- `MovieCard` — постер, название, год, рейтинг, кнопка "в избранное".
- `MovieGrid` — просто раскладывает массив `MovieCard` сеткой.
- `Loader` — спиннер на время загрузки.
- `ErrorMessage` — блок "что-то пошло не так".
- `EmptyState` — блок "ничего не найдено".

**Специфичные для страниц:**

- `SearchBar` — поле поиска, обновляет `?q=` в адресе.
- `GenreFilter` — выпадающий список жанров, обновляет `?genre=` в адресе.
- `CastList` — список актёров на странице фильма.
- `TrailerEmbed` — встроенное видео трейлера (YouTube iframe, TMDB даёт ключ видео).
- `Pagination` (или кнопка "Загрузить ещё") — пролистывание страниц каталога.

## 7. Пользовательский флоу

1. Пользователь открывает сайт → видит популярные фильмы на главной.
2. Вводит запрос в поиск → адрес меняется на `/?q=...`, список фильмов обновляется под запрос.
3. Выбирает жанр в фильтре → в адресе добавляется `&genre=...`, список сужается.
4. Кликает на карточку фильма → переход на `/movie/:id`, подгружаются детали, актёры, трейлер.
5. Нажимает "в избранное" (на карточке или на странице фильма) → фильм сохраняется в Zustand-хранилище и в `localStorage`.
6. Переходит на `/favorites` → видит все сохранённые фильмы.

## 8. Стилизация (Tailwind)

Tailwind — это набор готовых CSS-классов-утилит (`flex`, `p-4`, `text-lg` и т.д.), которые пишутся прямо в JSX-разметке вместо отдельных `.css`-файлов. Плюс для новичка: не нужно придумывать имена классов и держать в голове отдельный CSS-файл — стили видно прямо рядом с версткой. Минус, к которому нужно привыкнуть: JSX становится "многословнее". Отдельный `.css`-файл в проекте останется практически только для настройки шрифта и базовых стилей `body`.
